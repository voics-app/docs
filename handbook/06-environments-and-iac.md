# Environments and infrastructure as code

Summary: production, dev and local environments, and how env.sh and Terraform build and rebuild them.

The live list is the **Environments** database on the Discordy home page. The procedures are in [Environments](../runbooks/environments.md) and [Local development](../runbooks/local-development.md).

## The environments

| Environment | Where | Flux watches | Hostnames | Secrets |
|---|---|---|---|---|
| `gen-serv` (production) | Proxmox VM 107, 192.168.1.212, microk8s | `main`, `clusters/gen-serv` | `discordy*.voics.nl` | OpenBao `kv/discordy/*`, GitHub `production` environment |
| `dev` (dev and test) | its own small VM (Proxmox by default, Hetzner or AWS possible) | `develop`, `clusters/dev` | `discordy-dev*.voics.nl` | OpenBao `kv/discordy-dev/*`, GitHub `dev` environment |
| `local` | your workstation, Docker Compose | none | localhost | `.env` generated by `dev.sh`, never committed |

Every environment is one node running microk8s ([ADR-0008](../adr/0008-microk8s-reuse.md)). The dev environment follows `-dev.N` images from `develop`; production follows stable tags only.

## One command per environment

```bash
./env.sh plan <env>        # terraform plan (read-only)
./env.sh up <env>          # every stage; safe to re-run, finished stages report ok
./env.sh verify <env>      # bootstrap/60-verify.sh
./env.sh kubeconfig <env>  # fetch the kubeconfig
./env.sh destroy <env>     # terraform destroy, never for production
```

`up` runs these stages in order: `provision` (Terraform, then the node bootstrap scripts), `kubeconfig`, `flux`, `openbao`, `secrets`, `cloudflare`, `public-ip`, `wait` (every Flux layer Ready), `seed` (demo data, non-production only) and `verify`. The `openbao` stage creates the static seal key Secret (`openbao-seal-key`, copy in the key store), initialises with recovery keys and leaves OpenBao auto-unsealing (`SEAL_MODE=static` in `clusters/<env>/env.conf`, [ADR-0021](../adr/0021-openbao-auto-unseal.md)), so a reboot of any environment needs no manual unseal. `ONLY=stage1,stage2 ./env.sh up <env>` runs a subset.

## Terraform

`gitops/infra/terraform` has **node modules** (`node-proxmox`, `node-hetzner`, `node-aws`) that create the machine, a **cluster module** that runs the repo's own `bootstrap/05`, `10` and `15` scripts over SSH, and one **env root** per environment (`gen-serv`, `dev`, plus Hetzner and AWS examples). Adding a provider means one module and one env root. Credentials come from the environment only (`PROXMOX_VE_API_TOKEN`, `HCLOUD_TOKEN`, `AWS_PROFILE`, `GITHUB_TOKEN`, `CLOUDFLARE_API_TOKEN`) and are never written to a `.tf` file.

Production `gen-serv` is **adopted by import only**: never apply it blindly.

## Disaster recovery

Rebuilding production is `./env.sh up gen-serv` on a fresh node followed by the restore drills in [Backup and restore](../runbooks/backup-restore.md). The step list, including what to do with OpenBao keys, is in [Environments, Disaster recovery](../runbooks/environments.md#disaster-recovery-rebuild-production).

## Local stack

```bash
git clone --branch develop git@github.com:discordy-voics/gitops.git
cd gitops/local && ./dev.sh          # PowerShell: .\dev.ps1
```

`dev.sh` checks prerequisites, creates `.env` and JWT keys, builds the service images from sibling repos, starts the stack, seeds dev accounts and prints the URLs. Other commands: `status`, `logs [service]`, `down`, `reset`.
